# Vet Pulse — дашборд и собственный API

Сайт сохраняет оформление первой версии, но получает данные из серверного API и хранит записи в Cloudflare D1. Данные демонстрационные.

## Структура

- `public/` — HTML, CSS и JavaScript интерфейса.
- `worker/index.js` — HTTP API и обработчик сайта.
- `db/schema.ts` — схема Drizzle.
- `db/seed.json` — демонстрационные данные для первой инициализации.
- `drizzle/` — миграции базы. Уже применённые миграции не редактировать.
- `scripts/build.mjs` — сборка автономного Worker с ресурсами сайта.
- `scripts/test-api.mjs` — проверки на SQLite в Node.js 22+.

## API

Все маршруты находятся на том же домене, что и сайт. На размещённом сайте доступ ограничен платформой Sites.

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/health` | Состояние API |
| GET | `/api/dashboard` | Статистика, сравнения и исходы операций |
| GET | `/api/patients` | Демонстрационные пациенты |
| GET | `/api/appointments` | Записи 5–11 октября 2026 |
| GET | `/api/appointments?date=2026-10-05` | Записи конкретного дня |
| GET | `/api/operations?type=ortho` | Операции: all, soft, ortho, dental |
| GET | `/api/tasks` | Задачи и сохранённые статусы |
| PATCH | `/api/tasks/task-1` | Сохранение `{ "completed": true }` |

PATCH принимает JSON и требует совпадения Origin с доменом сайта. Весь API возвращает JSON и не кэширует данные.

В базе: шесть демонстрационных пациентов, 28 предстоящих записей, 342 демонстрационные операции за два года и три задачи. Исторические приёмы и уникальные пациенты хранятся как агрегированные отчёты; это не полная медицинская информационная система. Редактор пациентов и записи на приём не добавлен. Статусы задач сохраняются в базе. При первом запросе демонстрационные данные инициализируются атомарно и не перезаписывают существующие записи.

## Сборка и проверки

```sh
npm install
npm run build
node scripts/test-api.mjs
```

Сборка создаёт `dist/server/index.js` и миграции в `dist/.openai/drizzle`.

## Перенос на GitHub

Загрузите исходные файлы в репозиторий. Не загружайте `node_modules`, `.wrangler`, `.sites-runtime` или секреты. Эта версия содержит сервер: GitHub Pages может разместить только статическую часть и не выполняет API. Для переноса backend требуется Worker-хостинг с D1, применение SQL-миграций и привязка базы под именем `DB`. При размещении за пределами Sites необходимо настроить собственное ограничение доступа: платформа Sites защищает текущую публикацию, а код сам по себе не реализует вход по паролю.
